# `/prime`：新会话开工模板

> 根据已加载的项目规则和现有交接、计划与经验，确认当前进度和下一步。

## 什么时候用

- 继续同一个复杂任务时；
- 换一个 AI Agent 接手项目时；
- AI 忘记项目进度，需要重新接上任务时。

## 它解决什么问题

跨对话处理复杂任务时，不依赖旧聊天记录，而是让 AI 从项目文件中恢复可靠上下文，先弄清楚“目标是什么、已经做到哪里、下一步做什么”，再开始执行。

## 使用前准备

按项目复杂度准备以下文件；名称可以自行修改：

| 配置 | 文件 | 保存什么 |
| --- | --- | --- |
| 最低配置 | `CLAUDE.md` | 项目目标、范围、固定规则和 AI 必须遵守的边界；Claude Code 启动时自动加载 |
| 长任务建议 | `HANDOFF.md` | 当前进度、进行中事项、优先待办和跨会话交接 |
| 长任务建议 | `PLANS.md` | 长期目标、阶段计划和任务清单 |
| 进阶配置 | `PLAYBOOK.md` | 经过验证、以后仍可复用的经验、方法和避坑知识 |

小项目至少准备 `CLAUDE.md`。需要跨会话续做时增加 `HANDOFF.md`；任务阶段较多时增加 `PLANS.md`；长期经验逐渐积累后，再用 `PLAYBOOK.md` 单独维护。

## 可直接复用的指令模板

```markdown
# /prime — 新会话开工

开始工作前，请根据 Claude Code 已自动加载的项目规则恢复基础背景，再读取与本任务直接相关的交接、计划和经验；不要依赖旧聊天记录猜测现状。

## 1. 恢复当前任务

`CLAUDE.md` 无需重复读取。按以下顺序读取实际存在的可选文件；不存在就跳过，不要编造：

1. `HANDOFF.md`：最近完成、进行中事项、阻塞、优先待办和下一步；
2. `PLANS.md`：阶段目标、完成进度和未完成 checklist；
3. `PLAYBOOK.md`：只读取与本次任务有关的长期经验和避坑方法。

## 2. 核对当前任务

请确认：

- 本次最终要完成什么；
- 已经确认了哪些事实和决定；
- 已经完成什么；
- 目前正在做什么；
- 下一步最重要的动作是什么；
- 有哪些阻塞、风险或待用户确认的问题；
- 哪些文件或内容不能修改。

如果文件之间出现冲突，请列出冲突并等待确认，不要自行选择一个版本。

## 3. 输出开工简报

请严格使用以下格式：

### 当前目标
- 一句话说明本次任务结果

### 已完成
- 只列与本次任务直接相关的进展

### 当前进度
- 正在进行的阶段
- 计划完成度

### 下一步
1. 最具体、可以立即执行的动作
2. 后续动作

### 阻塞与边界
- 待确认问题
- 不能修改的内容

最后问我：“以上是否与当前状态一致？确认后我再继续执行。”
```

## 使用原则

- 只读取当前任务需要的文件，不要扫描整个电脑或整个知识库；
- 文件事实优先于 AI 对旧对话的记忆；
- 不存在的信息明确写“未找到”，不要猜；
- 在目标、权限或文件版本存在冲突时，先询问再行动；
- `/prime` 负责接上任务，不负责总结整个项目历史。
- Claude Code 会自动加载当前项目范围内的 `CLAUDE.md`，无须在指令中重复要求读取；
- 如果怀疑项目规则没有加载，可用 `/memory` 检查实际加载情况；
- `CLAUDE.md` 保存稳定的项目说明，不用来堆积每次任务产生的经验；
- 长期经验较多时，单独维护 `PLAYBOOK.md`，并只读取本次任务需要的部分。
