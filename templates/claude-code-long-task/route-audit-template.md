# `/route-audit`：项目文件整理模板

> 检查项目文档是否重复、错放、过载或失效，按严重程度给出修复建议。

## 什么时候用

- 项目文件逐渐变多、开始不知道信息放在哪里时；
- 同一规则在多个文件里重复出现时；
- 文件移动、重命名或删除后；
- 项目结构或工作流发生较大变化后；
- 长期项目定期整理时，例如每月一次。

它不需要每隔几天机械运行。小项目、文件没有变化时，可以不执行。

## 它解决什么问题

定期给项目文件做体检，找出重复职责、内容错放、文档过载、无用文件和失效引用，让 AI 和用户都能快速找到当前有效的信息。

## 使用前准备

在需要检查的项目目录中启动 Claude Code 即可。`CLAUDE.md` 会按 Claude Code 的规则自动加载；审计不要求项目必须存在 `HANDOFF.md`、`PLANS.md` 或 `PLAYBOOK.md`，也不需要为了运行审计提前创建任何文件。

## 可直接复用的指令模板

```markdown
# /route-audit — 项目文件健康检查

请只读检查当前 workspace 的实际文件结构、内容职责和文档引用。不要预设项目应该有哪些文件；先根据磁盘上的真实内容建立清单，再判断问题。先输出报告，不要直接移动、删除、合并或重写文件。

## 1. 建立文件清单

列出当前仍在使用的项目文件，并为每份文件写一句：

- 这份文件负责保存什么；
- 它是否仍在使用；
- 哪些其他文件会读取或引用它。

忽略缓存、临时文件、第三方代码和明确归档的历史文件。

## 2. 检查五类问题

### A. 职责重复

检查是否有两份以上文件在保存同一种规则、状态或流程。

### B. 内容错放

检查文件实际内容是否偏离它在项目中的真实职责，例如把临时进度、长期规则和历史记录混在同一份文件里。

### C. 文件过载

检查某份文件是否太长、主题太杂，已经难以定位或维护。

### D. 无效或过期

检查是否存在长期空置、已经被替代、内容过期但仍被当作当前入口的文件。

### E. 引用失效

检查被移动、删除或重命名的文件，是否仍被其他文档引用。

## 3. 判断严重程度

- 高：已经造成规则冲突、错误执行或读取错误版本；
- 中：内容重复、文件过载或职责不清；
- 低：命名、链接或目录提示需要更新，但尚未影响执行。

## 4. 输出审查报告

请使用以下格式：

# 项目文件健康检查

## 总览

| 检查项 | 状态 | 问题数 |
| --- | --- | --- |
| 职责重复 | 正常 / 注意 / 严重 | 数量 |
| 内容错放 | 正常 / 注意 / 严重 | 数量 |
| 文件过载 | 正常 / 注意 / 严重 | 数量 |
| 无效或过期 | 正常 / 注意 / 严重 | 数量 |
| 引用失效 | 正常 / 注意 / 严重 | 数量 |

## 问题清单

每个问题写清：

1. 涉及文件；
2. 发现了什么；
3. 为什么会影响使用；
4. 建议怎样处理；
5. 是否需要用户确认。

## 建议处理顺序

按“高 → 中 → 低”排列，并把可以一起处理的问题合并说明。

最后询问我：“是否按建议顺序修复？未经确认不要修改文件。”

## 5. 用户确认后再修复

只有获得明确确认后，才可以执行移动、合并、删除或重写。修改完成后再次检查：

- 旧引用是否已经更新；
- 是否出现新的重复文件；
- 当前唯一入口是否清楚；
- 被替代的旧文件是否已经退出使用。
```

## 使用原则

- 默认只检查和报告，不自动整理；
- 不因为文件很多就强行拆分，先判断是否真的影响查找和维护；
- 不删除历史证据或用户原始材料；
- 同一个当前规则尽量只保留一个维护位置；
- 不把“文件最近更新过”等同于“内容仍然正确”；
- 修改前先确认，修改后再次检查引用。
