# `/wrap = /handoff`：任务收尾与交接模板

> 任务收尾时更新进度和待办，生成下一会话可直接接手的交接文档。

## 什么时候用

- 完成一个阶段性任务时；
- 准备暂停、换会话或第二天继续时；
- 准备把项目交给另一个 AI Agent 时；
- 本轮出现了以后不能再踩的坑或可以复用的方法时。

## 它解决什么问题

把当前进度和交接信息统一写入 `HANDOFF.md`，再把真正可复用的长期经验单独写入 `PLAYBOOK.md`：下一会话能直接接着做，同样的错误也不会因为换会话而重复发生。

## 使用前准备

| 配置 | 文件 | 保存什么 |
| --- | --- | --- |
| 最低配置 | `CLAUDE.md` | 项目目标、范围、固定规则和 AI 必须遵守的边界；Claude Code 启动时自动加载 |
| 长任务建议 | `HANDOFF.md` | 当前进度、进行中事项、优先待办和跨会话交接 |
| 长任务建议 | `PLANS.md` | 长期目标、阶段计划和任务清单 |
| 进阶配置 | `PLAYBOOK.md` | 经过验证、以后仍可复用的经验、方法和避坑知识 |

## 可直接复用的指令模板

```markdown
# /wrap — 任务收尾与交接

请基于本轮实际完成的工作进行收尾。项目规则已经由 Claude Code 自动加载；按实际存在情况读取 `HANDOFF.md`、`PLANS.md` 和 `PLAYBOOK.md`，不要把推测写成事实，也不要修改与本任务无关的内容。

## 1. 核对本轮结果

请整理：

- 本轮任务目标；
- 实际完成的内容；
- 已确认的决定；
- 正在进行但尚未完成的内容；
- 当前卡点或等待事项；
- 下一步最具体的动作。

## 2. 更新交接文档

更新 `HANDOFF.md`，让一个完全没有上下文的新会话也能看懂当前进度并直接接手：

# Handoff

## 任务目标
- 最终要完成什么

## 本轮已完成
- 3—5 条真实结果

## 当前进度
- 正在进行的阶段
- 相关计划进度

## 进行中事项
- 已经开始但尚未完成的工作

## 未完成与卡点
- 尚未完成的工作
- 阻塞或等待用户决定的事项

## 优先待办
1. 下一会话应该先做什么
2. 然后做什么

## 必读文件
- 只列继续任务必需的文件

## 继续执行的边界
- 下一会话必须遵守的权限、范围或用户决定

`HANDOFF.md` 是滚动更新的当前交接，不要把所有历史一直追加进去。

## 3. 同步任务计划

更新 `PLANS.md`：

- 已完成步骤标记为完成；
- 未完成步骤保留；
- 新发现的步骤放入正确阶段；
- 已完全结束的计划标记为完成或归档；
- 不要为了看起来完整而虚构进度。

## 4. 单独沉淀可复用经验

这一部分与状态更新分开处理。重新回顾本轮过程，识别：

- 哪些做法被实际验证有效；
- 哪些错误已经找到明确原因；
- 哪些提醒以后处理相似任务时仍然适用；
- 哪些只是本次偶发现象，不能升级为长期经验。

再检查 `PLAYBOOK.md` 是否已有相同内容：

- 已有相似规则：更新原条目，不重复新增；
- 首次出现且以后还会用：新增一条简洁规则；
- 只对本次任务有效：留在 `HANDOFF.md`，不写进长期经验；
- 没有证据支持的原因推测：不要写成规则。

## 5. 输出收尾报告

请使用以下格式回复：

### 已更新
- 文件名：更新了什么

### 当前进度
- 已完成：
- 未完成：
- 下一步：

### 交接
- `HANDOFF.md` 已生成 / 本次无需生成

### 需要用户确认
- 没有则写“无”
```

## 使用原则

- `/wrap` 不是把聊天记录重新总结一遍，而是把不同信息写回职责对应的文件；
- 当前进度与跨会话交接统一写入 `HANDOFF.md`；
- `CLAUDE.md` 只维护稳定的项目说明、固定规则和执行边界；
- 长期有效的经验、方法和避坑知识写入 `PLAYBOOK.md`；
- 下一步必须具体到新会话可以立即执行；
- 只记录真实完成和真实卡点，不把计划写成成果；
- 写入前先检查旧内容，避免重复规则和重复待办。
